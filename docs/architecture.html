Rust LLM-powered MCP server v0.1.0 2026-08-21

产品介绍

kg-extract 是一个 Rust 知识图谱抽取库和 CLI 工具，从 Python graph.kg_extractor 忠实移植而来。它接收一段非结构化文本，输出一张 KnowledgeGraph——其中包含带类型的实体节点和带谓词标签的关系三元组。

面向的用户是构建知识图谱流水线的工程师：你可以用 CLI 直接抽取文档，也可以把 kg-extract 当库嵌入自己的 Rust 服务，或者通过 MCP 协议让它作为外部 AI Agent 的图构建工具。

与同类工具的核心差异：四套抽取策略（Simple / SchemaJson / ToolCall / Agentic）共享同一个 Extractor trait，背后插拔 LlmBackend（进程内 LLM SDK 或 Agent CLI 子进程）。同一份声明式 ExtractionSpec（schema + mode + 策略）可以在不同引擎之间切换，结果互换。

功能与特性

  • 四引擎抽取：Simple（分隔符 + 多轮精炼）、SchemaJson（schema-guided JSON）、ToolCall（工具调用，结构化输出免解析）、Agentic（单会话多轮 + 文档 grep），按场景选。
  • 三档 Schema 模式：Open（自由抽取）、Fixed（封闭世界，只允许 schema 内类型）、Evolving（种子 schema + 允许新增类型）。Fixed/Evolving 必须提供非空 seed schema。
  • 插拔 LLM 后端：LlmsBackend（进程内 llms crate）、SdkAgentBackend（minimaxcc / glmcc / mimocc 流式 Agent）、MockBackend（测试），统一 LlmBackend trait。
  • 确定性图构建：graph_build.rs 提供 entity_<md5> id 方案和名称解析，所有引擎和 MCP server 共享，输出互换。
  • 模糊合并与 coref：merger 支持精确/归一化/编辑距离/token-set 三条 coref 通道，类型门控，MergeStrategy 四档。
  • 来源追溯：每条实体和三元组携带 metadata.citations，行号/页码/bbox 三种精度，跨文档合并自动累积。
  • 37 套领域模板：presets（finance / legal / medicine / tcm 等 8 域）嵌入二进制，--preset general/concept_graph 一行启用。
  • MCP 图构建服务：kg-extract-mcp 暴露 add_entity / add_relation 等工具，外部 Agent 直接驱动。
  • 社区检测：label propagation + hierarchical Leiden，可选 GraphRAG 风格 --community-summaries 每社区一个 LLM 摘要。
  • Provider 自描述：kg.provider/v1 协议（describe / available / invoke），kg-acme 能力中心可自动发现和链式调用。

架构总览

chonkie 分块器负责把输入文本切成适合 LLM 上下文窗口的片段。默认的 Recursive 策略按词/句边界切分，Char 策略复现 Python 原版的字符滑动窗口，Token 策略按 tiktoken 真实 token 数分段。预分块输入（--input-format chunks）可直接灌入，跳过再分块。

抽取引擎层是四套策略的宿主。Simple 用分隔符提示 + 多轮精炼（gleaning）；SchemaJson 在 schema 约束下输出 JSON；ToolCall 让 LLM 调用 typed 工具（add_entity / add_relation）——输出天然结构化，免解析；Agentic 把整份文档放入一个多轮 SDK 会话，模型可 grep 文档，跨段落 coref 效果最好。四者共享 Extractor trait。

LLM 后端层屏蔽 LLM 服务差异。LlmsBackend 通过 llms crate 在进程内调用（OpenAI / Anthropic / Ollama 等）；SdkAgentBackend 驱动 Agent CLI（minimaxcc / glmcc / mimocc）的 stream-json 协议，支持原生多轮会话；MockBackend 返回确定性响应用于测试。

图构建核心（graph_build.rs + merger.rs）是所有引擎和 MCP server 的共享接缝。entity_id() 用 entity_<md5(name)[:8]> 生成确定性 id；merger 按小写 label 合并实体、按 (subj, pred, obj) 合并三元组，支持编辑距离（≥6 字符、相似度 ≥ 0.85）和 token-set（Jaccard ≥ 0.6）两条 coref 通道。

输出格式层将 KnowledgeGraph 序列化为 JSON（默认）、JSONL、kg-protocol（portable core-types 格式）、node-link（前端渲染）、Mermaid（文档内嵌）、stats（统计摘要），以及 ladybug-import（直接导入 LadybugDB 图数据库）和 communities（社区检测结果）。

主走查：「完整抽取」

  1. CLI 解析参数：用户传入 -e schema-json --schema-mode fixed --schema schema.json，CLI 创建 SchemaJsonExtractor，加载 ExtractionConfig（含 ExtractionSpec）。
  2. 分块：chonkie 的 Recursive 策略把文档切成若干段落，每段保留字符偏移量，后续用于行号追溯。
  3. LLM 推理：SchemaJson 引擎将 schema + 分块文本拼成 prompt 发给 LlmBackend；模型在 schema 约束下输出 JSON 格式的实体与关系。
  4. 解析：引擎解析 JSON，生成初步实体和三元组列表。解析器容错处理缺失字段和格式异常。
  5. Fixed 过滤：不在 seed schema 中的实体类型和关系类型被丢弃，记录到 schema_dropped_records。
  6. 图构建：graph_build 的 GraphBuilder 为每个实体生成 entity_<md5> id，通过名称解析关系端点，丢弃悬挂关系；merger 执行 lowercased label 去重。输出 JSON 格式的 KnowledgeGraph。

抽取策略详解

SimpleExtractor 用 GraphRAG 风格的分隔符格式提示 LLM 输出实体/关系，然后通过多轮 gleaning（"你漏掉了什么？"）提高召回率。它支持 open_session 原生多轮（SdkAgentBackend），或通过 ReplaySession 回放历史。

SchemaJsonExtractor 和 ToolCallExtractor 都是 schema 驱动的——共享 ExtractionSpec，只在机制上不同。SchemaJson 让 LLM 输出 JSON，ToolCall 让 LLM 调用 typed 工具。Fixed 模式下 ToolCall 通过 JSON-Schema enum 约束参数，SchemaJson 先 parse 再 drop。

AgenticExtractor 是差异最大的一个：它把整份文档写进 tempdir，在只读 sandbox（Read/Grep/Glob）里让 Agent 逐段抽取。一个连续会话保证了跨段落的一致性——同一个实体名不会分裂成多个节点。代价是串行、速度较慢。适合中小篇幅、对一致性要求高的场景。

图构建与合并

图构建核心是所有引擎的共享接缝，保证不同引擎输出可互换。

entity_id()
对实体名做 MD5 取前 8 位：entity_<md5[:8]>，确定性 id。
GraphBuilder
累积实体（小写 label 去重），通过名称（大小写不敏感）解析关系端点，丢弃悬挂关系。
merger
三条 coref 通道：精确 → 归一化（去冠词/法人后缀）→ fuzzy（编辑距离 ≥ 0.85、token-set Jaccard ≥ 0.6），类型门控。
MergeStrategy
KeepExisting（默认）/ KeepIncoming / FieldUnion / Llm（异步模型合成）。

merger 合并实体时自动累积两侧的 metadata.citations——跨文档合并后，一个实体能追溯到所有出现过的文档。

架构特征与取舍

  • 引擎可互换：同一 ExtractionSpec 可跑 SchemaJson 也可跑 ToolCall，结果形状一致。代价是每种引擎有自己的 fallback 语义，需要分别测试。
  • Agentic 是 coref 策略而非 recall 策略：单会话保证实体名一致性（62KB 文档：Simple 516 碎片 vs Agentic 136），但丢失一些细粒度实体。去碎片效果不可被 post-hoc merge 复现。
  • 来源追溯由代码计算，不依赖 LLM：chunker 记录字符偏移，代码推导行号/页码/bbox。模型永远不数行号。
  • Schema 模式正交于机制：Fixed/Evolving 用不同方式在不同引擎中实现（ToolCall: JSON-Schema enum；SchemaJson/Agentic: parse-then-drop + 反馈），但外部契约一致。
  • 确定性输出：entity_id 方案和 merger 保证相同输入→相同图。社区检测用固定 seed，成员排序。
  • Provider 协议：kg.provider/v1 让 kg-extract 在 kg-acme 能力中心中自描述，hub 不硬编码 provider 枚举。
